## Tooling breakthrough — full Site Inventory coverage achieved for the first time

Today's usual sheet pull (`get_file_metadata` MAX_ALLOWED) truncated before even reaching the Site Inventory tab — a pure size-budget artifact, not a sheet change. Instead of re-pulling the same way, tried Drive's `download_file_content` with an xlsx export on the same file. **This returned the entire workbook — all 34 tabs (15 visible + 19 hidden) — as a real .xlsx file**, which a subagent decoded and opened with pandas/openpyxl. Result: **19,043 of 19,043 Site Inventory rows read in full (100% coverage)**, matching the tab's own header banner exactly, with complete Category/Brand/Brand-Category/Product coverage for the first time ever (every prior Mon/Thu read had zero visibility into non-Product page types). Full write-up and recommendation in `seo-ops/registry.md` — this looks like it should become the new standard pull method going forward, replacing the chronically-truncating text-snippet approach, pending a few more days of confirming it stays reliable.
